# 记账规则

本文同时规定已实现的领域规则和后续采集器必须满足的契约。标有“后续”的部分尚未接入运行。

## 分开统计层级

物理接口、应用传输、回环和代理连接是不同层级。同一次浏览器下载经过本机代理时可能出现多次观测；这些字节不能跨层相加作为总用量。

接口计数包含局域网等经过接口的流量，不等于 ISP 账单或无线空口全部开销。应用与接口之间的差额可能涉及封装、重传、卸载和缺失，不能全部称为协议开销，也不能自动分摊到应用。

## 已实现：累计计数差分

`CounterReading` 包含接口身份、计数纪元、UTC 时间及独立的上传/下载累计字节。`CounterDeltaCalculator` 是无状态规则，不会替调用方保存基线。

| 条件 | 结果 | 调用方后续责任 |
|---|---|---|
| 第一个样本 | BaselineEstablished，无测量字节 | 保存首次基线，不把启动前累计量入账 |
| 接口变化 | InterfaceChanged，无测量字节 | 旧接口和新接口独立维护状态，记录边界 |
| 计数纪元变化 | EpochChanged，无测量字节 | 建立新纪元基线；重启后即使累计量更大也不能跨纪元减 |
| 时间相等或回退 | TimeNotIncreasing，无测量字节 | 不用过时样本覆盖有效基线；系统时间重置另作质量事件处理 |
| 任一方向计数下降 | CounterDecreased，无测量字节 | 重建纪元和基线并记录缺口，不做无符号回绕推算 |
| 同一接口/纪元，时间和计数有效 | Measured，两个方向分别做整数差分 | 保存有效当前样本；测得零字节仍是有效观测 |

无测量时 `Volume` 和 `Duration` 为 null。实际零用量的 `Volume` 是有值的 `(0, 0)`。字节使用 64 位无符号整数，聚合使用 checked 运算，禁止溢出后继续生成看似正常的数据。

基础差分的 UTC 间隔用于样本顺序和时间边界，不是速率计时器。现有 InterfaceTrafficSession 的实时速度使用独立 Stopwatch 单调间隔，精确字节仍用 ulong，仅在显示速率时转为浮点数。

## 已实现：接口内存会话

每个接口独立维护基线和本次运行累计；切换查看接口不会混合状态，没有整机跨接口合计。首次有效差分前累计为 null，测得零字节后才显示零。运行会话只含有效区间；已提交 SQLite 的历史在关闭后保留。

API 失败、接口消失/离线、观察到身份或纪元变化、任一方向回退、采样间隔超过五秒、电源通知均打断连续性。UTC 不递增或墙钟间隔与单调间隔相差超过两秒时也重建基线。恢复首样本不补算缺口，后续样本从新基线继续；已测累计保留，断档次数可见，当前速率不可用时不能显示为零。

接口计数观察键现在仅包含 LUID 和索引，NetworkGuid 留给网络归属层。这使计数连续而网络变化的区间仍有可分配字节；不能把网络归属变化误当成计数器重置。离线、驱动复位等计数不可靠区间仍重建基线。未改变可见字段且累计仍变大的复位可能无法察觉，当前不能承诺发现每次断线或重置。

## 已实现：Wi-Fi 候选分账

只对物理 WLAN 候选逐接口记账，不将其与 TUN、回环、过滤接口相加。分账需明确启用，首个 Wi-Fi 观察只建立归属基线，不将之前的接口区间追记到网络。暂停/恢复、睡眠通知后清除归属基线，已有有效记录保留。

候选键由 SSID 原始字节的十六进制表示、区分大小写的配置名、Windows NetworkGuid、BSS 类型、认证和加密类型组成。缺失 Windows 网络上下文时不创建身份。BSSID 只用于发现接入点变化，不属于候选键；同一候选漫游后继续使用同一记录。不同上下文/配置/安全类型的同名网络分开，但字段完全相同的不同实际网络仍可能无法区分，人工合并/拆分尚未实现。

计数读取被前后连接查询和通知序列夹取。连接开始、结束、断开、漫游、接口/配置变化等相关通知推进版本，扫描完成和信号强度变化不打断分账。通知仅消费头部，不保留原生负载；回调异常降级。所有以下分配只针对已有的有效接口差分：

| 证据 | 分配 |
|---|---|
| ACM/MSM 未完整订阅或回调失败 | 未识别网络 |
| 前后观察不稳定、通知版本变化、已知身份或接入点变化 | 整个区间进入边界未分配，不按时间或字节比例猜测 |
| 稳定观察但身份缺失、权限失败等 | 未识别网络，不沿用旧名称 |
| 两端稳定、版本和候选及接入点一致 | 分给该网络候选 |

一次查询内发生变化时，当前端点不稳定，会保护它两侧的相邻区间。API 失败/离线/休眠等没有可靠计数差分时，不制造“未分配字节”；断档由接口质量状态表达。

同一接口、同一启用范围内：`有效观察字节 = 各候选已分配字节之和 + 边界未分配 + 未识别网络`，两个方向分别使用 checked ulong 精确核对。启用时间不同或停采缺口造成的总览/分账范围差异不称作协议开销。窗口内账本通过独立来源累计快照保存到 SQLite；暂停期间不制造零测量。

## 已实现：应用事件内存账本（实验）

每次明确开始创建新会话纪元，独立保留 TCP4/TCP6/UDP4/UDP6 的接收与发送 size，不与接口、Wi-Fi 或代理数字相加。当前系统的受控回环中，size 与测试进程的 socket 收发量及第二条会话的类型化解析一致；公网、重传/卸载、封装及更广系统覆盖仍待验证，不称为互联网出口字节。只消费指定 Send/Recv，不额外叠加重传/复制/连接事件。Windows rundown 中的 PID 0 空闲伪进程不创建应用身份，也不计为拒收；若网络事件出现 PID 0，其字节仍进入未知桶。

按已观察的生命周期区分 PID 复用；rundown 首见时间不等于实际启动时间，不向前补记。无法确认实例时保留未知。发现时间乱序、丢失增加或健康计数读取失败时，将既有归属撤回未知并要求新身份，避免继续使用可能过期的进程名。达到 4096 实例容量时新身份进入降级，事件字节继续归入未知。所有接受事件在各方向/协议下均满足 `观察量 = 各实例 + 未识别`；拒收或根本未送达的事件无法捏造字节。

无事件时观察量为 null，有效零事件才是零。停止保留最终快照，再次开始替换当前页记录；已保存历史保留，电源边界停止。见 [ADR 0003](decisions/0003-application-etw-validation.md)及 [ADR 0005](decisions/0005-local-history-ssh-reports.md)。

## 后续网络验收约束

- 网卡稳定身份与网络身份分别保存；不能把会变化的接口索引当作唯一永久身份。
- 候选字段需经更多真实网络验证再冻结；后续支持人工合并/拆分。
- 同名网络可能不同，同一网络可能跨 AP 漫游；不能只按 SSID 或 BSSID 简单决定全部历史归属。
- 读取名称失败时保留接口级数据并标记，不能沿用上一个网络。
- 无法确定切换前后的计数差记录为边界未分配，不按时间比例伪造精确分账。
- 多出口和代理分流下，不根据单个默认路由猜测所有应用的出口。

## 已实现：代理单一计量源

代理 API 逻辑总量、连接连续差分与 ETW/接口分别展示。每个连接 ID + start 生命周期每区间计一次，不因代理链多个节点而重复累计；不把 ETW 原应用或核心进程字节加到本页。首次基线、失联、核心进程实例变化或计数回退均中断连续性。原应用要求 API 两侧 TCP/进程实例证据及相邻观察的身份一致，否则可测差分归未知。UDP/TUN 不满足证据时不猜测。

短连接在两次快照之间结束时可能消失，首次前段和关闭尾部缺失；不按比例补齐，也不把非原子的核心总量减去连接明细当作精确未知。连接视图自身满足 `观察差分 = 分组 + 容量溢出`；核心总量是独立视图，不与明细再相加。完整规则见 [ADR 0004](decisions/0004-proxy-accounting.md)。

## 已实现：SSH 客户端候选

SSH 经过代理时，SSH 与代理专题是重叠视图。跳板、连接复用、端口转发内部业务可能只能显示隧道总量。远端主机自身下载不等于本地下载，只有实际经过本机的数据进入本地账本。

已知客户端名称与生命周期 + TCP 四元组/连接实例形成候选，不把端口 22 单独作为协议证据。新出站/22 端口或精确用户规则可进入统计，已有非标准端口需规则。用户别名不改变底层计量。元数据不确认协议或最终服务器；转发可能产生额外候选腿，不声称专题总量是唯一 SSH 加密传输字节。

## 已实现：历史与完整性

事实保留来源/层级、捕获纪元、序列、UTC 范围、分区、质量。事实与累计检查点同事务，重放不重复入账；未知较新模式拒绝降级。应用/SSH 撤回身份时，已有历史在原时间改列未知并守恒。整数以 TEXT 保全 UInt64，报表 checked 聚合，不用浮点/SQLite SUM。失败重试可恢复累计差分，不能恢复区间时间细分；未提交崩溃数据不保证恢复。

日期范围转为所选时区的 UTC 半开区间，结束日期含当天，周从周一开始。按观察结束时间归账，不按比例拆分跨账期采样。有效零与无观察分开，报表显示部分区间和质量提示；没有全天完整覆盖证明。关闭期间不采集。详见 [ADR 0005](decisions/0005-local-history-ssh-reports.md)。
