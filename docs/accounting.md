# 记账规则

本文同时规定已实现的领域规则和后续采集器必须满足的契约。标有“后续”的部分尚未接入运行。

## 分开统计层级

物理接口、应用传输、回环和代理连接是不同层级。同一次浏览器下载经过本机代理时可能出现多次观测；这些字节不能跨层相加作为总用量。

接口计数包含局域网等经过接口的流量，不等于 ISP 账单或无线空口全部开销。应用与接口之间的差额可能涉及封装、重传、卸载和缺失，不能全部称为协议开销，也不能自动分摊到应用。

## 已实现：累计计数差分

`CounterReading` 包含接口身份、计数纪元、UTC 时间及独立的上传/下载累计字节。`CounterDeltaCalculator` 是无状态规则，不会替调用方保存基线。

| 条件 | 结果 | 调用方后续责任 |
|---|---|---|
| 第一个样本 | BaselineEstablished，无测量字节 | 保存首次基线，不把启动前累计量入账 |
| 接口变化 | InterfaceChanged，无测量字节 | 旧接口和新接口独立维护状态，记录边界 |
| 计数纪元变化 | EpochChanged，无测量字节 | 建立新纪元基线；重启后即使累计量更大也不能跨纪元减 |
| 时间相等或回退 | TimeNotIncreasing，无测量字节 | 不用过时样本覆盖有效基线；系统时间重置另作质量事件处理 |
| 任一方向计数下降 | CounterDecreased，无测量字节 | 重建纪元和基线并记录缺口，不做无符号回绕推算 |
| 同一接口/纪元，时间和计数有效 | Measured，两个方向分别做整数差分 | 保存有效当前样本；测得零字节仍是有效观测 |

无测量时 `Volume` 和 `Duration` 为 null。实际零用量的 `Volume` 是有值的 `(0, 0)`。字节使用 64 位无符号整数，聚合使用 checked 运算，禁止溢出后继续生成看似正常的数据。

当前的 UTC 间隔用于样本顺序和时间边界，不是单调速率计时器。后续实时速度应使用独立单调时钟。

## 后续：网络身份和切换

- 网卡稳定身份与网络身份分别保存；不能把会变化的接口索引当作唯一永久身份。
- 网络候选标识由连接配置和 SSID 原始字节等组成，具体字段经验证冻结；支持人工合并/拆分。
- 同名网络可能不同，同一网络可能跨 AP 漫游；不能只按 SSID 或 BSSID 简单决定全部历史归属。
- 读取名称失败时保留接口级数据并标记，不能沿用上一个网络。
- 无法确定切换前后的计数差记录为边界未分配，不按时间比例伪造精确分账。
- 多出口和代理分流下，不根据单个默认路由猜测所有应用的出口。

## 后续：代理和 SSH

代理 API 用于增强归属。短连接在两次快照之间结束时可能消失，尾部字节也可能缺失；这不能通过加大轮询频率完全解决。核心重启创建新纪元。接口总量、代理逻辑字节、原应用字节分别展示覆盖范围和可信度。

SSH 经过代理时，SSH 与代理专题是重叠视图。跳板、连接复用、端口转发内部业务可能只能显示隧道总量。远端主机自身下载不等于本地下载，只有实际经过本机的数据进入本地账本。

## 后续：历史与完整性

事实数据保留测量来源和层级。缺口、未知归属、ETW 丢失、API 断连必须可查询。UTC 存储、按选定时区汇总；跨日/月和时钟变更单独测试。同口径明细到聚合的字节应精确一致，显示单位可以舍入。
