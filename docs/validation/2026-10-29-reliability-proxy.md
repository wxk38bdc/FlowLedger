# ETW 可靠性与代理关联实测

日期：2026-10-29。环境：本机 Windows x64、.NET 10、TraceEvent 4.0.0。管理员采集由用户授权，密钥由用户只在桌面本地输入；没有读取 Clash 配置或密钥。本文只保留匿名结论和合成负载，不提交本机原始输出、连接清单、端口、网络名称、凭据或测试核心二进制。

## ETW 可靠性

`--verify-reliability 30` 三轮均通过；每轮独立采集纪元、第二条类型化 ETW 参考及新测试进程。每轮包含 QUIC v4、QUIC v6、4 路持续 TCP v4/v6 各 30 秒，随后排空会话。所有测试进程观察到唯一 Start/Stop；生产与类型化参考逐传输/方向精确一致；双方零已知丢失，生产零拒收、无身份/容量降级，分区守恒。

- QUIC 每次合成业务收发合计 393216 B，两端在同一测试进程；UDP 事件 size 各方向约 418000–420000 B，与参考一致，包含 QUIC/TLS/UDP 相关开销，不强迫等于业务字节。不验证 HTTP/3 语义或解密内容。
- 持续 TCP 每轮各方向累计约 1.06–1.23 GB，精确等于已确认的 socket 送达量；这是四个长连接、节流的本机负载，不是任意并发/最大吞吐承诺。
- 双消费者父进程每轮测量窗口约 36 秒（包含等待），整机归一化 CPU 约 0.09%–0.13%，工作集采样最大约 66–70 MiB；不含工作进程 CPU 或内核缓冲区，也不保证瞬时峰值。
- 独立 `--watch-apps 60` 在自然背景下约 61 秒结束：零已知丢失/拒收、无身份降级、守恒成立；进程 CPU 约 781 ms，归一化整机比例约 0.040%，工作集采样最大约 56 MiB。不称为受控空闲或长期内存结论。

最初 QUIC 合成测试握手失败。诊断确认 Windows SChannel 不接受直接生成的 ephemeral 私钥；使用内存 PFX 导入且不设置 PersistKeySet 后，正常释放时清理系统临时密钥容器，v4/v6 完整传输成功。没有安装/信任证书或写出 PFX，没有改变系统 TLS。最终代码移除了临时详细诊断，只输出不含地址/路径的错误类型和代码。

## 异常恢复

新增本用户随机 owner 标识，位于 LocalApplicationData/FlowLedger/etw-owner.id；它不是密钥，不含流量。会话名包含 kind、owner、PID、进程创建时间与采集纪元。启动明确启用的管理员采集时，只检查匹配此 owner 的 App/Reference 新格式会话；所属进程仍活跃、无法确认或名字不匹配时不停止。PID 被复用时用创建时间排除旧实例。标识损坏时失败关闭，不覆盖标识或扩大回收范围。

真实 `--verify-etw-recovery`：停止由该验证方法创建的准确会话后，源显示 Faulted；终止该方法创建的测试采集进程后，确实观察到残留会话，下一次启动回收 1 条，新的源 Running，原残留已消失。结果 FaultVisible=true、AbandonedObserved=true、Recovered=1、Clean=true。只终止自有辅助进程，没有终止用户客户端或其他工具。原有 `--validate-apps` 三轮回归亦通过。

合成回归覆盖活跃/不明/其他用户/旧格式不回收、回收失败质量可见、事件丢失/乱序降级及启停排空。未主动使原生 ETW 缓冲区溢出，不声称硬件上的丢失恢复全部通过。

## Clash 与 Mihomo

Clash：用户当前 CFW 同时开启规则、系统代理和 TUN。初次联动因实际控制器端口已经变化而不可用；新增“查找本机控制器”后，用户在本地输入密钥并确认“本机代理验证通过”。本软件生成的无密钥摘要也为 Passed/Delivered=true、唯一已确认测试连接、核心增量可读、零断档/重置。只记录当前实例，不推断任意内核版本。

Mihomo：下载[官方 v1.19.33](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.33)，按 GitHub 官方资产 SHA-256 核对。使用独立目录、随机 loopback 端口与随机测试密钥，DIRECT、TUN/DNS 关闭，不接管系统代理；未改动用户的 Clash。三轮本机 HTTP/mixed 验证通过，后来对最终的核心归属检查再次三轮通过。测试结束停止自有核心并删除临时密钥配置。官方二进制、配置和原始日志仅在忽略的 artifacts 目录，不随项目发布。

验证经核心传输本机合成 1 MiB 响应，要求完整送达、唯一原应用 TCP 连接与非零 API 连接增量。已分配量约为响应的一部分：首次基线和关闭尾部不补记，不将其伪装成完整 1 MiB。核心逻辑总量与连接明细不相加；ETW、物理接口和代理链节点也不叠加。单元回归另验证重复 ID、链长度不改变一次计量、PID 复用、计数回退、失联/时钟跳变、容量未知守恒、认证/重定向/响应上限、核心重启及前后身份不一致。

隔离核心的错误测试密钥返回 401 / AccessDenied，不生成代理探测。相同监听端口、相同版本的核心重启实测：恢复后状态 Available、Resets=1，没有负数、巨大差分或沿用旧纪元；新的连续零差分为有效零，未观察的连接量仍 null。CLI 对断档/重置结果返回 1，表示部分观察。

`--verify-tcp-owners` 另在真实本机 TCP4/TCP6 连接上核对源/目的四元组与测试 PID，均通过；不公开地址、端口或 PID。它核对原生读取布局与归属，不验证真实 TUN 地址重写。

## 放行边界

当前实现及上述有界验收已完成；整体 V1 继续保留未完成项。真实 TUN/UDP 原应用、公网直连/代理链、重传/卸载、跨会话全进程可见性、真实 PID 复用、主动原生丢失、极限压力及 72 小时稳定性未验收。Wi-Fi 切换/漫游/睡眠、SSH、SQLite 和后台采集也没有因此完成。支持范围以[矩阵](../support-matrix.md)为准。

自动化回归当前 173 项；CI 不启动特权采集、测试核心或受控流量，只运行合成回归及已有只读诊断。完整策略见[代理 ADR](../decisions/0004-proxy-accounting.md)和[ETW ADR](../decisions/0003-application-etw-validation.md)。
