# ETW 受控回环验证结论

日期：2026-10-29。对应 V1-04/V1-05 的部分验收；两项不整体放行。环境为本机 Windows x64、.NET 10、TraceEvent 4.0.0，用户授权的提升后管理员令牌。这里只保留脱敏结论和合成探测参考量；原始本机输出留在被忽略的 artifacts 中，不入库。

## 发现与修复

初始版本的 `--verify-apps` 三轮都观察到四类传输双向流量，socket 参考与事件 size 一致、无已知丢失，但每轮一条拒收导致退出 1。Windows 启动时会枚举 PID 0 空闲伪进程，原领域逻辑把它当作无效应用身份。现在忽略此身份事件；PID 0 的网络字节仍保留未知，真正负 PID/空名异常不放宽。独立参考每轮确认一个 idle rundown，没有非空闲空名 rundown；修复后三轮拒收归零。

## 方法与参考边界

`--validate-apps` 每轮新建生产会话与 `FlowLedger.Reference.<随机 GUID>`，均为有限内存会话，不创建 ETL。第二会话用 TraceEvent 类型化 size 和其由负载修正的 ProcessID，不调用生产原生解码器或领域生命周期算法；只对测试进程累计，不读取目的地址/端口或捕获报文内容。后台真实应用流量不进入此文档。

控制器为每个探测启动独立工作进程；父进程充当回环服务端，工作进程作为客户端。两端使用不同的发送/接收量，可以检查方向颠倒。父进程先登记测试 PID，再通知工作进程开始；两端确认全部 socket 字节送达。测试进程退出后等待缓冲并停止/排空两条会话，要求每个目标唯一 Start/Stop、生产账本恰好一个非 rundown 实例。若进程号在此期间复用，参考歧义不能算通过。

逐实例、四种传输与两个方向比较 `生产账本 = 类型化参考 = 受控 socket 量`；其他传输类型应为零。同时要求双方健康、无已知丢失，生产无拒收/身份失效/容量不足，且全部已接受事件的进程+未知分区守恒。第二解析路径仍共享内核事件源，因此不证明独立的事件完整送达。socket 量在这些回环条件下的相等，也不证明其他路径的 size 语义。

## 实测结果

三轮各 16 个独立进程，共 48 个实例全部通过，命令退出 0。各轮生产与参考 LostEvents=0、生产 RejectedEvents=0、IdentityUncertain=false、CapacityReached=false、PartitionsMatch=true。

| 每轮探测 | 子进程数 | 每个子进程的合成 socket 参考 | 结论 |
|---|---:|---|---|
| TCP4 / TCP6 方向 | 2 | 各发送 131072 B、接收 65536 B，1 条连接 | 协议/方向、实例及两种参考精确一致 |
| UDP4 / UDP6 方向 | 2 | 各 8 次交换，每次发送 1024 B、接收 512 B | 精确一致 |
| TCP4 / TCP6 短连接 | 2 | 各 24 条连接，每条发送 257 B、接收 127 B | 精确一致；三轮共 144 条短连接 |
| UDP4 / UDP6 短交换 | 2 | 各 24 次，每次发送 257 B、接收 127 B | 精确一致 |
| 并发 TCP4 / TCP6 | 8 | 各发送 8 MiB、接收 4 MiB | 精确一致；每轮业务收发合计 96 MiB |

并发部分每轮约 0.125–0.148 秒，包含子进程启动/结束及回环服务；按已送达业务收发量计算约 649–768 MiB/s。这是很短的本机内存/协议栈突发，不能视为网卡带宽、持续采集能力或 CPU 压力峰值。三轮整个双会话父进程测量窗口各约 6.3–6.4 秒，包含等待；其资源不等同于单采集器。

修复后的 `--verify-apps` 另执行三轮，CoveragePassed=true、State=Stopped、LostEvents=0、RejectedEvents=0。普通用户下 watch/verify/validate 仍返回 AccessDenied、退出 1，不启动探测；非法参数退出 2。

独立 `--watch-apps 30` 在自然背景下正常结束，State=Stopped、质量计数正常、分区守恒。测量约 30.62 秒，进程 CPU 约 531 ms，按逻辑处理器数量归一化的整机 CPU 比例约 0.054%，工作集采样最大约 43.1 MiB、私有内存约 20.7 MiB。内存每秒采样，可能漏掉瞬时峰值；不含内核会话缓冲区，不代表整机总开销，也不将背景环境称作空闲或可重复受控负载。

用户手动确认管理员桌面“开始应用统计”能出现记录，点击“停止应用统计”后保留记录。自动输入未能可靠操作提升窗口，因此该项来源是用户验收。已发布修复版并更新既有桌面快捷方式；关闭后丢失记录的原型设计不变。完整 GUI 关闭/重启/电源流程未单独验收。

Release 构建零告警/错误，131 项自动化回归和格式检查通过。新增回归防止空闲身份污染健康、探测越界、方向反转、双侧无数据误通过、错误传输、缺少送达/生命周期或不明确实例仍被判成功。普通 CI 只运行这些合成回归，不启动特权 ETW 或回环工作进程。

## 尚未验收

- 真实 PID 复用、缺失 Start/Stop 的现场恢复；现有 PID 复用/丢失规则只有合成回归。
- QUIC、外部主机、公网、系统代理、TUN、重传/卸载及字节层次含义；当前 0 B 差异仅限表中受控回环场景。
- 持续并发/吞吐、主动丢失、资源峰值、长期内存、72 小时稳定性、崩溃/残留会话恢复。
- 实际不同/同名 WLAN 切换、漫游、拒绝位置权限、睡眠恢复和多出口的硬件验收。
- 原应用/代理去重、SSH 连接归属、后台服务、持久历史和日周月报表。

下一步优先补 QUIC、持续负载/资源及故障恢复，再扩展公网/代理路径与支持矩阵。不给上述未测场景添加通过标记。
