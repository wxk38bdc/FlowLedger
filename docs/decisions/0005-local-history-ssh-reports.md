# ADR 0005：SSH 元数据专题、本地 SQLite 与双语报表

日期：2026-10-29。状态：已实现窗口内版本；后台服务、真实 TUN 验证及完整 SSH 场景验收不在本次完成范围。

用户明确选择暂缓真实 TUN 路径验证，优先交付 SSH、本地 SQLite、报表和中英文界面。此顺序调整不表示此前未完成的 V1 验收已经通过。

## SSH 的识别与计量

明确启动的 SSH 采集复用已有 ETW 生命周期与健康处理，另开自有会话，与应用页独立启停。仅此模式读取 TCP v2 端点元数据；普通应用采集仍不保留连接地址。不读取 SSH 配置、凭据、命令行或报文内容，不解析协议或扫描服务器。

已知客户端文件名包括 ssh/scp/sftp、Xshell/XshellCore、PuTTY/Plink。名称只是候选证据，PuTTY/Plink 等也可能使用其他协议。Windows Terminal 自身不作为 SSH 客户端。只接纳这些客户端的新建出站 TCP 连接、远端 22 端口，或用户明确配置的精确 IP + 端口规则；已存在的非标准端口连接需要用户规则。规则可设置别名，限 128 条，支持 IPv4 / 无 scope 的 IPv6，不做 DNS 查询。编辑后在下一次开始生效。

按捕获纪元、PID 生命周期、TCP 四元组和连接观察实例区分多会话与重连。连接结束或进程退出只关闭匹配记录；停止后排空并保留本次记录。全局事件乱序、身份失效或已知丢失撤回既有 SSH 归属到未知；容量溢出也进入未知，已接纳字节守恒。无法识别为候选的流量不进入 SSH 总量。

本机 OpenSSH v4/v6 对照确认经典 TCP v2 的 saddr/sport 表示所属连接的本地端，接收事件也保持这一排列；字节方向另由 send/recv 事件确定。不能仅按字面“接收”反转地址。此结论对应已验证的本机 Windows 场景，其他系统仍需验收。字段布局参考 [Microsoft ETW 文档](https://learn.microsoft.com/en-us/windows/win32/etw/tcpip-typegroup1) 和固定版本 [TraceEvent 解析器](https://github.com/microsoft/perfview/blob/v4.0.0/src/TraceEvent/Parsers/KernelTraceEventParser.cs)。

跳板、ProxyCommand 和端口转发只显示本机可见端点；不能从本机流量推算最终目标或远端自身下载。一个客户端还可能产生转发 TCP 腿，候选汇总不是唯一 SSH 加密传输量；按端点分行保留，不把它称为服务器互联网账单。复用连接不拆成每个终端/通道。SSH 是 ETW 应用字节的专题子集，不能与应用、代理或接口合计。

## 本地数据库

默认路径：`%LOCALAPPDATA%\FlowLedger\history.sqlite3`。运行窗口自动保存已观察的数据，原有 Wi-Fi、应用、代理及新 SSH 模块仍需分别明确启用。没有服务、后台 IPC、关窗采集或断档补算。历史数据库与报表功能不依赖管理员权限。

采用 Microsoft.Data.Sqlite.Core 10.0.10、SQLitePCLRaw.bundle_e_sqlite3 3.0.5、原生 SQLite 3.53.4。避开默认旧原生包的已知漏洞，不关闭 NuGet 审计。连接禁用池化，设置外键、5 秒忙等待；WAL、FULL 同步，模式版本为 1，拒绝降级未知较新模式。参考 [Microsoft.Data.Sqlite](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/)、[事务](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/transactions) 与 [SQLite WAL](https://sqlite.org/wal.html)。

每个模块继续按原采集节奏观察，存储按来源/纪元合并最新累计快照，正常每 5 秒形成事务批次；停止、查询和退出立即排空，故障时提前重试。合并保留质量标记；最新失败帧不会覆盖待写的有效测量。批次包含来源、独立层级、捕获纪元、递增序列、时间、质量、累计分区。事实和累计检查点在同一事务内：

- 批次 GUID + 内容哈希保证相同重放只计一次；相同 GUID 不同内容、陈旧序列、不同层级混用、没有新纪元的计数回退或分区不守恒均拒绝，整个批次回滚。
- `frames` 记录采样与质量，`checkpoints` 保存已提交累计量，`facts` 保存精确差分及时间。没有观察时只保存质量，不产生零字节测量。
- 空闲区间仅保存一次零增量观察，不为每个历史进程重复写零行；报表明确标为已观察的零增量。WAL 报表使用独立延迟读取事务，不占写入锁。
- 字节以十进制 TEXT 保存，读取为 UInt64，逐方向 checked 相加。SQLite INTEGER/SUM 无法覆盖完整无符号 64 位范围，不用浮点或强转近似。累计溢出明确失败。
- 应用/SSH 因身份失效撤回累计分区时，事务内将本纪元已保存的对应历史事实改列未知，保留原区间时间和字节，再写新差分。后续报表不会继续展示已撤销的应用名。
- 数据库写入失败保留各来源/纪元最新累计快照，下次采样或退出重试；恢复后的差分标记 StorageGap，不能恢复丢失的区间时间细分。尚未成功提交的内容在进程崩溃时可能丢失。退出前有未保存快照会明确提示，不声称全部保存。

SQLite 自身处理事务崩溃恢复，不能补回未采集或未提交的数据。数据库是本机未加密文件，可能含接口名、SSID 候选、进程名、SSH 地址/别名和规则；不含控制器密钥、SSH 凭据、命令行或流量内容，不上传。不提交数据库、旁路文件或真实使用记录。没有自动保留期、自动备份和容量清理；这些继续留在 M3。

## 报表

只能查询一个独立来源：每张接口、每张接口下的 Wi-Fi 分区、应用、代理核心、代理连接或 SSH。接口层永不跨接口合计。应用按文件名汇总；SSH 按别名/可见服务器/端口/客户端/证据汇总；Wi-Fi 保留不同候选身份，即使同名也不合并。

日期选择为所选时区的起止日期，结束日期包含当天，内部转换成 UTC 的 `[开始, 下一天)`。支持日/周/月分组及自定义范围总计；周从周一开始。支持 Windows 时区与 DST 23/25 小时日边界，歧义午夜选择较早 UTC 时刻；跳过不存在的午夜。单次最多 367 天。

事实按观察结束时间归账；跨日/周/月的采样区间不按比例推断字节，边界误差取决于实际采样/停止排空间隔。首次样本、离线或失败没有有效观察，空白不能视作零。有效零测量单独保留。行内标记部分区间，页内显示质量提示数量。当前没有“全天完整覆盖”的判断。

CSV 导出查询快照，含来源、账期、对象、整数收发量、区间数、部分区间数、质量提示、时区和 UTC 范围。文本按 CSV 引号规则转义，对以公式标志开头的名称增加文本前缀；用户自行选择本地导出位置。当前导出含实际名称，不自动匿名化。

## 界面与验收

七页导航；常用动作在前，详细口径折叠。最小窗口 1040×740，长表有滚动/省略与悬停完整文本，SSH 的收发列优先可见。简体中文 / English 即时切换，选择保存在 SQLite。动态状态保留双语值，独立于视觉树的表格列使用明确绑定源更新表头。单实例限制减少重复采集窗口。

自动化覆盖分区守恒、PID 复用/重连、容量/丢失降级、事务回滚/幂等/重开、UInt64、时区/DST、公式转义、设置持久化、错误重试，以及两种语言七页布局和表头。真实 SQLite 异常退出与 OpenSSH 非标准端口本机 v4/v6 验证单列，见[本轮记录](../validation/2026-10-29-ssh-history.md)。这些不代表已验证真实远端认证、文件传输、跳板/转发或长期可靠性。
