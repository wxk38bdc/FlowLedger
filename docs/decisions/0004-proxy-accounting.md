# ADR 0004：只读核心 API 代理账本与保守 TCP 关联

日期：2026-10-29。状态：已实现并验证当前 Clash 实例及隔离 Mihomo 1.19.33 的本机显式代理；完整 TUN/公网不放行。

## 访问与认证

用户明确启用后，只向字面量 loopback IP 的 HTTP/HTTPS 根地址发送 GET `/version`、`/connections`。禁止 URL 内凭据、查询、片段、自定义路径、远端/主机名；关闭系统代理、Cookie 和重定向，保持 HTTPS 默认验证。密钥由本地 PasswordBox 或操作者明确提供的 `FLOWLEDGER_CONTROLLER_SECRET` 输入，不读取 Clash 配置、订阅或客户端密钥；不会放进 CLI 参数、异常消息或报告。停止释放客户端，清除密钥引用；不保存密钥文件，也不承诺托管字符串能逐字节擦除。

API 请求前确认控制器端口与 HTTP/mixed 入口同属一个可见进程实例，避免向已换属的本机端口发送密钥；API 读取后再次确认。无法核对时保留 CoreUnconfirmed，不继续用旧身份计量。认证失败、格式错误、超时与核心身份不足分别显示。每个请求三秒、整次读取（含正文）四秒超时；响应最大 2 MiB、JSON 深度 32、最多 4096 条连接，拒绝重复连接 ID、负数/非整数计数、缺失必要字段及控制字符版本字符串。

“查找本机控制器”仅检查 HTTP/mixed 入口所属 Clash/Mihomo 进程的 loopback/通配监听，不扫描其他进程或读取配置。最多检查 16 个候选，只发送不带密钥的 `/version` 请求。唯一端口的成功版本或 401 返回候选；多个/过多/不可确认时要求手动填写。候选发现不等于认证成功，启用时仍需再次核对。用户实测曾遇到核心控制器端口变化，修复后通过此入口重新连接。

## 两种独立的 API 观察量

`ProxyUsageLedger` 分开维护：

- 核心逻辑累计计数的连续区间差分。
- 活动连接 ID + start 生命周期的连续区间差分，按原应用/入站/核心报告路径分组。

两个视图都只来自核心 API；不与 ETW 原应用、核心进程、回环、TUN 外层、物理接口、代理链节点字节相加，也不从 ETW 原始记录中武断扣除 API 字节。每个连接每个区间只记一次，与代理链长度无关。这是当前去重的范围，不是覆盖整机所有路径的统一去重总量。

首次启用、每个新连接、暂停/失败/长间隔、时钟异常、核心进程实例变化、核心/连接计数回退、连接 ID 生命周期变化均重新建立相应基线。失联期间不补算。核心纪元由本机监听进程 PID + 创建时间确认，不能仅凭版本号；相同版本核心重启也必须新纪元。

活动快照会漏掉初次观察前字节、关闭尾部，以及两次轮询间完成的整个连接。全局计数和连接字段读取不是原子操作，不强迫两者完全相等，不用负数或比例摊分制造守恒。连接观察量本身始终精确满足 `已观察连接差分 = 分组之和 + 容量溢出未知`；最多保留 4096 个分组，溢出继续记入未知。无可靠区间仍为 null；已测零差分才是零。

## 原应用证据

GetExtendedTcpTable 的 IPv4/IPv6 OWNER_PID 表只临时用于匹配。每个候选进程读取 PID、创建时间及末级进程名，不读命令行或完整路径。API 读取前后两张表都必须支持同一归属；进程创建时间不能晚于连接开始。核心进程不能被当作原应用。

| 入站 | TCP 确认条件 |
|---|---|
| HTTP / HTTPS / SOCKS4 / SOCKS5 | source IP/port 对应本机已建立的客户端连接，远端是 loopback + 已确认核心入口端口 |
| TUN | API source 和 destination 的完整四元组都与本机已建立连接一致 |
| 其他、UDP、缺失/歧义、进程已退出、字段变化 | 原应用未知 |

不会信任 API 报告的 process/processPath 来冒充已确认的 Windows 进程，也不按文件名猜归属。两次轮询的身份不一致时，该区间的可测字节归未知，不改名追溯旧记录。假 IP、地址重写、短连接和 UDP 的限制保留；TUN 四元组规则目前仅有合成回归，不能当成真实 TUN 全覆盖。入站类型与 DIRECT/代理链标签是核心报告证据，不独立证明物理出口或网络路径。

原生/API 地址只在明确启用的关联读取中短暂处理，不写入领域账本、CLI 或报告；不抓取报文内容。桌面显示进程名/PID，CLI 仅显示匿名槽位、是否确认及分类。关闭窗口丢失用量；ETW owner 标识和无密钥合成验证摘要是单独的运行辅助文件，不是流量历史库。

## 验证与限制

桌面“验证本机代理”和 CLI `--verify-proxy` 在本机创建合成 HTTP 服务，经指定 HTTP/mixed 入口传输 1 MiB 响应。要求完整送达、唯一已确认的测试原应用连接、非零且不超过合成响应合理上界的 API 分配量、核心增量可读及零断档/重置。首次基线和尾部导致记录少于 1 MiB 是预期，不把文件大小当作所有层的真值。测试不改变代理规则；规则不允许本机回环时结果不足，不自动改成 DIRECT。

当前 Clash 实例由用户本地输入密钥并操作，脱敏摘要及用户确认通过。Mihomo 官方 v1.19.33 下载包按官方 SHA-256 核对，在独立数据目录、随机本机端口、随机临时密钥下运行；DIRECT、TUN/DNS 禁用，不接管系统代理。三轮成功，另验证错误认证及同端口核心重启。测试核心结束并删除临时配置；二进制/配置/原始输出不随项目分发。

完整结论见[实测报告](../validation/2026-10-29-reliability-proxy.md)和[支持矩阵](../support-matrix.md)。不认证任意核心版本，不承诺 UDP 原应用、真实 TUN、公网代理链去重、短连接全量或运营商账单精度。
